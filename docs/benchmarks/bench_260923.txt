10. HOW TO READ THE STATISTICS

Statistic                         | Meaning                                                                      
----------------------------------+------------------------------------------------------------------------------
Median / ns                       | Middle repetition result; primary typical-time comparison.                   
Mean / ns                         | Arithmetic average of the repetition results.                                
Stddev / ns                       | Sample standard deviation; spread of repetition results around their mean.   
IQR / ns                          | 75th percentile minus 25th percentile; spread of the middle half of results. 
CV / %                            | 100 * sample standard deviation / mean; variability relative to average time.
Minimum / ns                      | Fastest observed repetition result; not a guaranteed achievable time.        
Maximum / ns                      | Slowest observed repetition result; not a worst-case latency guarantee.      
Iterations per repetition / count | Batch/lifecycle executions used to produce each repetition result.           
Repetitions / count               | Independent reported samples of a benchmark case; 20 here.                   

IQR uses inclusive linear-interpolated quartiles. Stddev uses the sample formula
(divisor n - 1). Tables are rounded only for display; calculations use unrounded
raw values. Google Benchmark aggregate CV rows store a fraction: 0.10 means 10%,
even if their inherited time_unit field says ns.

12. MEASUREMENT BOUNDARIES

Function suffix (all three formulas) | Work inside each timed iteration                                                       
-------------------------------------+----------------------------------------------------------------------------------------
Native                               | Execute the dedicated native formula over one batch.                                   
BytecodeExecute                      | Execute one batch using an already prepared bytecode executor.                         
BytecodeCreateDestroy                | Construct the execution blueprint and executor, then destroy them. No records executed.
BytecodeCreateExecuteDestroy         | Construct the blueprint/executor, execute one batch, then destroy them.                

The input Program, record dataset and external output buffer are prepared outside
the timed loop where applicable. CreateDestroy has no batch-size argument because
it does not process records. CreateExecuteDestroy directly measures the combined
lifecycle; separately measured medians need not add exactly because execution
conditions differ and measurements vary. A lower combined result is not proof
that rebuilding the executor makes execution faster.
